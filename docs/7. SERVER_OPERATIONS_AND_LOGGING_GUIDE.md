# 🚀 Cẩm Nang Vận Hành Server, Quản Lý & Đọc Log Hệ Thống

Tài liệu này cung cấp hướng dẫn toàn diện cho **Lập trình viên (Team Members)** và **AI Assistant** về quy trình vận hành server phát triển (Dev Server), cơ chế Hot Reload, cấu trúc lưu trữ log tập trung và phương pháp phân tích/truy vết lỗi khi gặp sự cố.

---

## 1. ⚙️ Quy Trình Vận Hành Server Với `server.sh`

Dự án cung cấp sẵn script điều khiển server chuẩn hóa tại thư mục gốc: [`server.sh`](../server.sh). Toàn bộ thành viên trong nhóm có thể sử dụng trực tiếp qua Terminal.

```
                ┌──────────────────────────────────────────────┐
                │          Script ./server.sh                  │
                └──────────────────────┬───────────────────────┘
                                       │
         ┌───────────────────┬─────────┴─────────┬───────────────────┐
         ▼                   ▼                   ▼                   ▼
  ./server.sh start   ./server.sh start -d  ./server.sh stop  ./server.sh clean
  (Chạy tương tác)    (Chạy ngầm Daemon)   (Tắt triệt để)    (Dọn cache .next)
```

### 📋 Bảng Lệnh Điều Khiển Chuẩn

| Lệnh thực thi | Phím tắt qua NPM | Chế độ chạy | Mô tả chi tiết |
| :--- | :--- | :---: | :--- |
| `./server.sh start` | `npm run dev` | **Foreground** | Chạy trực tiếp ở Terminal, thấy log realtime, bấm `Ctrl + C` để dừng. Tự động ghi đồng thời vào `logs/server.log`. |
| `./server.sh start -d` | - | **Background** | Chạy ngầm (Daemon), giải phóng terminal. Toàn bộ log lưu vào `logs/server.log`. |
| `./server.sh stop` | `npm run server:stop` | - | Quét và tiêu diệt triệt để (`kill -9`) mọi process chiếm dụng cổng `3000`. |
| `./server.sh restart` | `npm run server:restart` | - | Tắt server cũ và khởi động lại ngay lập tức. |
| `./server.sh restart -d` | - | - | Khởi động lại server ở chế độ chạy ngầm. |
| `./server.sh status` | - | - | Kiểm tra xem server có đang hoạt động không, PID và URL cổng `3000`. |
| `./server.sh logs` | - | - | Mở luồng stream log thời gian thực (`tail -f logs/server.log`). Bấm `Ctrl + C` để thoát. |
| `./server.sh clean` | - | - | Xóa sạch thư mục cache `.next` & `.turbo`, sau đó tự động restart server mới tinh. |
| `./server.sh build` | `npm run build` | - | Chạy kiểm tra biên dịch TypeScript (`tsc`) và Next.js build trước khi commit. |

## 2. ⚡ Cơ Chế Hot Reload & Khi Nào Cần Restart Server?

### 2.1. Sửa Code Bình Thường (KHÔNG CẦN Restart Server)
Nhờ tính năng **Fast Refresh (HMR)** của Next.js:
- Khi chỉnh sửa file `.tsx`, `.ts`, `.html`, `.css`, `.module.css`: Bạn **chỉ cần bấm Lưu (`Cmd + S`)**, Next.js sẽ tự động cập nhật lên trình duyệt trong **< 1 giây**.
- Nếu chỉnh sửa Server Action hoặc Data Fetching: Chỉ cần bấm **Reload trình duyệt (`Cmd + R` hoặc `F5`)**, **không cần restart server**.

### 2.2. Các Trường Hợp BẮT BUỘC Phải Restart Server (`./server.sh restart`):
1. ⚙️ **Chỉnh sửa file cấu hình hệ thống:** `next.config.mjs`, `tsconfig.json`, `package.json`.
2. 🔐 **Thay đổi biến môi trường:** Thêm/sửa key trong file `.env`, `.env.local`.
3. 📦 **Cài đặt thư viện mới:** Vừa chạy `npm install <package>`.
4. 🔄 **Kẹt cổng hoặc lỗi cache đơ:** Khi gặp lỗi `EADDRINUSE: port 3000 is already in use` hoặc code không nhận cập nhật lạ ➔ Chạy `./server.sh clean`.

## 3. 📁 Cấu Trúc File Log Tập Trung (`logs/`)

Toàn bộ log của ứng dụng được tập trung tại thư mục `logs/` ở thư mục gốc dự án (đã nằm trong `.gitignore`):

```text
typi-code/
├── logs/
│   ├── server.log               # 🖥️ Log của Console/Next.js (Compile errors, HMR, HTTP request traces)
│   ├── app.log                  # 📝 Log nghiệp vụ của Pino Engine (SQL, HTTP Client, Auth, Actions)
│   └── app.2026-09-18.01.log    # 📦 Log xoay vòng tự động (khi app.log vượt trần 5MB)
```

### Phân vai giữa 2 file log:
- **`logs/server.log`:** Chứa toàn bộ những gì xuất ra màn hình Terminal của Node.js/Next.js (Bắt các lỗi crash runtime, lỗi cú pháp TypeScript lúc compile, lỗi 404/500 của Next.js).
- **`logs/app.log`:** Chứa log cấu trúc JSON có định danh, thời gian, request context do thư viện logger chuẩn (`@repo/shared`) ghi lại.

## 4. 🔍 Hướng Dẫn Đọc & Phân Tích Log Cho Lập Trình Viên (Member Guide)

Khi kiểm thử (test) chức năng hoặc gặp lỗi, thành viên có thể mở trực tiếp file `logs/app.log` và `logs/server.log` trong IDE để tra cứu:

### 4.1. Các Tag Giám Sát Tự Động Quan Trọng Cần Chú Ý:

| Tag xuất hiện trong Log | Ý nghĩa | Hành động cần thực hiện |
| :--- | :--- | :--- |
| `[SLOW_SQL]` | Câu lệnh Prisma/SQL chạy chậm ($\ge 50ms$). | Kiểm tra Index bảng hoặc tối ưu câu lệnh truy vấn. |
| `[SLOW_API]` | API bên thứ 3 (Platzi/External) phản hồi chậm ($> 1000ms$). | Kiểm tra đường truyền mạng hoặc bật cache tầng server. |
| `[SLOW_ACTION]` | Server Action render hoặc xử lý chậm ($> 500ms$). | Tối ưu logic tính toán hoặc chia nhỏ tác vụ. |
| `[HTTP_ERR]` | Lỗi gọi REST API (400, 401, 403, 500). | Xem chi tiết payload gửi đi và response lỗi từ backend. |
| `[AUTH_FAIL]` | Đăng nhập thất bại / Sai mật khẩu. | Kiểm tra thông tin tài khoản hoặc hash password. |

### 4.2. Cách Truy Vết Lỗi Bằng Correlation ID (`requestId`):
Mỗi một lượt request người dùng thực hiện đều được gắn một `requestId` duy nhất (Ví dụ: `req_1726889200_abc`). 
- Khi người dùng báo lỗi, bạn chỉ cần copy `requestId` này và **Search (`Cmd + F`)** trong file `logs/app.log`.
- Toàn bộ chuỗi sự kiện: từ lúc nhận request ➔ gọi API nào ➔ chạy câu SQL nào ➔ gặp lỗi ở dòng nào sẽ hiển thị liên tục theo thứ tự thời gian.

## 5. 🤖 Hướng Dẫn Phối Hợp Với AI Assistant Khi Gặp Sự Cố

Cả bạn và AI đều có quyền truy cập trực tiếp vào hệ thống file log. Khi gặp lỗi, bạn không cần phải copy từng dòng log dài dòng vào khung chat!

### Mẫu câu yêu cầu AI fix lỗi siêu nhanh:

```markdown
"Server đang báo lỗi 500 khi tôi truy cập trang /login. Hãy đọc file logs/server.log và logs/app.log để tìm nguyên nhân và sửa giúp tôi."
```

### Quy trình AI tự động xử lý khi nhận lệnh:
1. **Quét log tự động:** AI đọc phần log mới nhất trong `logs/server.log` và `logs/app.log`.
2. **Xác định Root Cause:** Định vị chính xác file, số dòng (`line:col`) và đối tượng dữ liệu gây ra lỗi (Null pointer, Zod validation fail, Prisma constraint violation...).
3. **Áp dụng bản vá (Hotfix):** Sửa trực tiếp code và thông báo kết quả đã được khắc phục.

## 6. 🛠️ Bảng Xử Lý Sự Cố Nhanh (Troubleshooting FAQ)

| Hiện tượng | Nguyên nhân | Cách khắc phục nhanh |
| :--- | :--- | :--- |
| `Error: listen EADDRINUSE: address already in use :::3000` | Có một tiến trình server cũ đang chạy ngầm chưa tắt. | Chạy `./server.sh restart` hoặc `./server.sh stop`. |
| Giao diện bị đơ, sửa code không thấy thay đổi | Cache Next.js `.next` bị xung đột nội bộ. | Chạy `./server.sh clean` (xóa cache và restart tự động). |
| Muốn tắt toàn bộ server chạy ngầm | Quên PID của process daemon. | Chạy `./server.sh stop`. |
| Muốn kiểm tra server có đang chạy ổn không | Cần kiểm tra trạng thái trước khi test. | Chạy `./server.sh status`. |
