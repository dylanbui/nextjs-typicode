## 1. 🎯 TRIẾT LÝ CỐT LÕI (CORE PHILOSOPHY)

Mô hình hướng tới mục tiêu: **"1 Thư Mục = 1 Plugin Tự Trị Hoàn Chỉnh (Autonomous Plugin)"**.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                 TRIẾT LÝ 4 KHÔNG TRONG KIẾN TRÚC MODULE                     │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. ❌ KHÔNG phân mảnh file: 100% mã nguồn module nằm trong app/[module]/    │
│ 2. ❌ KHÔNG lồng folder rườm rà: Dùng 1 file [[...slug]]/page.tsx duy nhất. │
│ 3. ❌ KHÔNG tải JS thừa: Views là Server Components (0KB JS Bundle).        │
│ 4. ❌ KHÔNG lộ URL nội bộ: _feature được Next.js bảo vệ tự động (0ms leak).│
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. 📁 CẤU TRÚC THƯ MỤC CHUẨN (DIRECTORY BLUEPRINT)

Khi tạo module mới (ví dụ: `login`, `posts`, `products`, `orders`, `users`), cấu trúc thư mục bắt buộc như sau:

```
apps/web/src/app/[module_name]/
│
├── _feature/                               # 🔒 Private Folder (Next.js loại bỏ khỏi URL Routing)
│   │
│   ├── schemas/                            # 📜 1. SCHEMAS: Zod Validation Isomorphic (Dùng chung)
│   │   └── [module].schema.ts              # -> FilterSchema, FormSchema, ParamsSchema
│   │
│   ├── actions/                            # ⚡ 2. ACTIONS: Server Only (import 'server-only')
│   │   ├── [module].server.tsx             # -> Dispatcher Action Handlers (indexAction, editAction...)
│   │   └── [module]_mutations.server.ts    # -> Server Actions ('use server') thêm/sửa/xóa Database
│   │
│   ├── views/                              # 🎨 3. VIEWS: Giao diện hiển thị
│   │   ├── [Module]ListView.tsx            # -> Dumb Server View (HTML tĩnh, 0KB JS Bundle)
│   │   └── [Module]FormView.client.tsx     # -> Interactive Client View ('use client')
│   │
│   ├── components/                         # 🧩 4. CLIENT LEAVES: UI tương tác nhỏ
│   │   ├── [Module]FilterBar.client.tsx    # -> Thanh search / filter URL debounce
│   │   └── [Module]ItemActions.client.tsx  # -> Nút bấm tương tác client
│   │
│   ├── stores/                             # 📦 5. STORES: Client State (Zustand)
│   │   └── [module].store.client.ts        # -> Quản lý state UI Client ('use client')
│   │
│   └── index.ts                            # 📦 Responsible Barrel Export có kiểm soát
│
└── [[...slug]]/
    └── page.tsx                            # 🎼 MASTER DISPATCHER: Cổng vào điều phối duy nhất
```

## 3. 🛡️ QUY CHUẨN ĐẶT TÊN HẬU TỐ & LƯỚI BẢO VỆ SERVER-CLIENT

Để **triệt tiêu 100% rủi ro rò rỉ mã nguồn Server vào Client Bundle (Bundle Poisoning)**, toàn bộ dự án áp dụng nghiêm ngặt bộ quy tắc sau:

### 3.1. Quy ước 4 Nhóm Hậu Tố File:

| Nhóm File | Hậu tố bắt buộc | Môi trường chạy | Quy tắc an toàn |
| :--- | :--- | :---: | :--- |
| **1. Server-Only Logic** | `*.server.ts`<br>`*.server.tsx` | **Node.js Server** | Bắt buộc đặt `import 'server-only'` ở dòng đầu tiên. Chứa Prisma, Secret Key, Bcrypt. ❌ Cấm Client Component import. |
| **2. Client-Only Views** | `*.client.tsx`<br>`*.client.ts` | **Browser Client** | Bắt buộc có `'use client'` ở dòng 1. Chứa hooks, DOM events, Zustand UI stores. |
| **3. Shared Isomorphic** | `*.schema.ts`<br>`*.types.ts`<br>`*.shared.ts` | **Cả 2 môi trường** | Chứa Zod schema, TypeScript interfaces, hàm tính toán thuần túy (không đụng Node `fs` hay `window`). |
| **4. Default RSC Pages** | `page.tsx`<br>`layout.tsx` | **Server Component** | React Server Component mặc định của Next.js App Router. |

### 3.2. Lưới Bảo Vệ Tự Động Build-Time (`server-only`):
Gói thư viện chính thức `server-only` được cài đặt tại `apps/web`. Bất kỳ file nào có dòng `import 'server-only'` nếu bị import nhầm vào Client Component sẽ bị **Next.js chặn đứng ngay lập tức lúc Compile và báo lỗi thẳng vào Terminal**, không bao giờ để lọt ra trình duyệt!

```typescript
// src/lib/prisma.server.ts
import 'server-only'; // 🛡️ Lá chắn bảo vệ vàng
import { PrismaClient } from '@prisma/client';
// ...
```

### 3.3. Mô Hình Barrel Export Có Trách Nhiệm (`index.ts`):
File `index.ts` trong `_feature/` đóng vai trò là Public API của module, được tổ chức có phân khu rõ ràng:

```typescript
// apps/web/src/app/[module]/_feature/index.ts

// 1. 🔄 Shared Types & Schemas (An toàn cho cả Server & Client)
export * from './schemas/[module].schema';

// 2. 🎬 Server Dispatcher Action Handlers (Chỉ chạy trên Server)
export * from './actions/[module].server';

// 3. ⚡ Server Actions Mutations (Chỉ gọi qua Server Action RPC)
export * from './actions/[module]_mutations.server';

// 4. 🎨 Client Views & Components (Chỉ dùng khi render UI Client)
export * from './views/[Module]FormView.client';
```

## 3. 🎼 MÔ HÌNH ĐIỀU PHỐI URL THỐNG NHẤT (`ActionDispatcher`)

Toàn bộ hệ thống TypiCode áp dụng duy nhất một cơ chế điều phối chuẩn: **`ActionDispatcher`** (`dispatchAction`) từ `@repo/shared`:

### Nguyên lý hoạt động:
* **Tự động ánh xạ URL $\rightarrow$ Action Function (Convention over Configuration)**:
  * `/posts` $\rightarrow$ gọi `indexAction(rawSearchParams)` hoặc `listAction()`
  * `/posts/add` (hoặc `/posts/new`) $\rightarrow$ gọi `addAction()`
  * `/posts/123` $\rightarrow$ gọi `viewDetailAction(123)` (tự động nhận diện ID số)
  * `/posts/update/123` (hoặc `/posts/edit/123`) $\rightarrow$ gọi `updateAction(123)` hoặc `editAction(123)`
* **Lifecycle Hooks mạnh mẽ**: Hỗ trợ hook `before` (Auth/RBAC Permission Guard), `after` (Logging, Telemetry), `onError` (Tập trung bắt lỗi).

### Mã nguồn chuẩn `page.tsx` cho mọi module:

```tsx
// apps/web/src/app/(main)/[module]/[[...slug]]/page.tsx
import * as moduleActions from '@/app/(main)/[module]/_feature';
import { dispatchAction } from '@repo/shared';

interface PageProps {
  params: Promise<{ slug?: string[] }>;
  searchParams: Promise<Record<string, string | string[] | undefined>>;
}

export default async function ModuleMasterPage({ params, searchParams }: PageProps) {
  const { slug } = await params;
  const rawSearchParams = await searchParams;

  return await dispatchAction(
    moduleActions,
    slug,
    rawSearchParams,
    {
      moduleName: 'ModuleName',
      defaultActionNames: ['indexAction', 'listAction', 'index', 'list'],
      idFallbackActionNames: ['viewDetailAction', 'detailAction', 'detail'],
      before: (ctx) => console.log(`[Before] ${ctx.actionName}`),
      after: (_res, ctx) => console.log(`[After] ${ctx.actionName} in ${Date.now() - ctx.startTime}ms`),
    }
  );
}
```

## 4. ⚖️ BẢNG ĐÁNH GIÁ ƯU ĐIỂM & NHƯỢC ĐIỂM (PROS & CONS)

| Tiêu Chí Đánh Giá | Mô Hình Truyền Thống (Nested Folders) | 🚀 Mô Hình Mới (`_feature` + Dispatcher) |
| :--- | :--- | :--- |
| **Số lượng Folder Route trong `app/`** | 4-6 folders (`/add`, `/[id]`, `/edit/[id]`...) | 🟢 **1 folder `[[...slug]]` duy nhất** |
| **Tính tự chứa (Cohesion)** | Bị xé nhỏ qua nhiều thư mục | 🟢 **100% tập trung tại `app/[module]/`** |
| **Tái sử dụng / Đóng gói Plugin** | ❌ Rất khó copy, dễ thất lạc file | 🟢 **Chỉ cần copy cả thư mục `app/[module]/`** |
| **Kích thước JS tải về Browser** | Tải code render của trang về Client | 🟢 **0KB JS Bundle** (RSC pre-render HTML) |
| **Tốc độ hiển thị trang đầu (FCP)** | 800ms - 1.5s (Phải đợi Client fetch) | 🟢 **< 100ms** (HTML render từ Server) |
| **Bảo vệ URL nội bộ** | ⚠️ Dễ vô tình expose public route | 🟢 **Next.js Private Folder (`_`) chặn 100%** |

## 5. 🛠️ CÁC ĐIỂM HẠN CHẾ & GIẢI PHÁP KHẮC PHỤC (WORKAROUNDS)

| Hạn Chế Của Next.js App Router | Nguyên Nhân | 👉 Giải Pháp Khắc Phục Chuẩn |
| :--- | :--- | :--- |
| **1. `loading.tsx` chung toàn module** | Next.js chỉ nhận 1 file `loading.tsx` ở cấp `[[...slug]]`. | Bọc `<Suspense fallback={<Skeleton />}>` trực tiếp trong từng file Action / View riêng biệt. |
| **2. `error.tsx` chung** | 1 file `error.tsx` bắt lỗi cho toàn bộ các sub-action. | Sử dụng `<ErrorBoundary>` của React hoặc khối `try-catch` trả về `ErrorView` trong Action. |
| **3. SEO & `generateMetadata`** | Không có file `page.tsx` riêng cho từng trang con. | Tái sử dụng `switch (route.type)` hoặc Dispatcher trong `generateMetadata({ params })`. |
| **4. Intercepting Routes (`(..)photo`)** | Phụ thuộc 100% vào File-System router của Next.js. | Dùng Modal Client thông thường hoặc Query Param (`?modal=add`). |
| **5. Cross-Route Import** | Import xuyên thấu từ `_feature` của route này sang route khác. | Đưa các components/schemas dùng chung ra `@repo/shared` hoặc `@/components`. |

## 6. 🚀 ĐỀ XUẤT NÂNG CAO: REGISTRY OBJECT + LAZY DYNAMIC IMPORT (ENTERPRISE SCALE)

*(Định hướng kỹ thuật cho các module có nhiều tác vụ xử lý nặng như xuất PDF, Excel, xử lý đồ họa)*

Để tối ưu hóa **RAM Server** và đảm bảo **Zero Prototype Pollution**, giải pháp **Registry Object + Lazy Dynamic Import + Zod `paramsSchema`** được áp dụng:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│               MÔ HÌNH REGISTRY OBJECT + LAZY IMPORT + ZOD PARAMSSCHEMA                 │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ 1. 🛡️ Whitelist Registry     │ Định nghĩa tường minh các Action được phép kích hoạt.    │
│                               │ Chặn 100% việc gọi hàm ẩn / __proto__ / prototype.     │
├───────────────────────────────┼────────────────────────────────────────────────────────┤
│ 2. ⚡ Lazy Dynamic Import     │ Chỉ nạp file action vào Server RAM khi URL được gọi.   │
│    () => import(...)          │ Giảm tối đa Server Cold-start và RAM Footprint.        │
├───────────────────────────────┼────────────────────────────────────────────────────────┤
│ 3. 📜 Zod ParamsSchema Tuple │ Từng Action tự làm chủ luật kiểm tra tham số của mình. │
│    z.tuple([z.number()])      │ Tự động reject URL sai kiểu trước khi hàm thực thi.    │
└───────────────────────────────┴────────────────────────────────────────────────────────┘
```

```ts
// 1. Từng Action độc lập kèm Zod Param Validation
// app/posts/_feature/actions/post_detail.action.tsx
import { z } from 'zod';

export async function viewDetailAction(id: number) {
  const post = await postRepository.getPostById(id);
  return <PostDetailView post={post} />;
}
viewDetailAction.paramsSchema = z.tuple([
  z.number().int().positive('ID bài viết phải là số nguyên dương'),
]);

// 2. Action Registry Object với Lazy Dynamic Import
// app/posts/_feature/actions.registry.ts
export const postActionRegistry = {
  index: () => import('./actions/post_list.action').then((m) => m.indexAction),
  list: () => import('./actions/post_list.action').then((m) => m.listAction),
  add: () => import('./actions/post_add.action').then((m) => m.addAction),
  edit: () => import('./actions/post_edit.action').then((m) => m.editAction),
  delete: () => import('./actions/post_delete.action').then((m) => m.deleteAction),
  viewDetail: () => import('./actions/post_detail.action').then((m) => m.viewDetailAction),
} as const;

export type PostActionKey = keyof typeof postActionRegistry;
```

## 7. 📝 QUY TRÌNH 6 BƯỚC TẠO MODULE MỚI (STEP-BY-STEP CHECKLIST)

Khi bắt đầu tạo một module mới tên là **`[name]`** (ví dụ: `customers`, `invoices`, `reports`):

### ✅ Bước 1: Tạo cây thư mục
```bash
mkdir -p apps/web/src/app/[name]/_feature/{schemas,actions,views,components}
mkdir -p apps/web/src/app/[name]/[[...slug]]
```

### ✅ Bước 2: Tạo Schema xác thực (`_feature/schemas/[name].schema.ts`)
* Định nghĩa `[Name]FilterSchema` (cho query URL).
* Định nghĩa `[Name]FormSchema` (cho Form client & Server mutation).

### ✅ Bước 3: Tạo các Dumb Views (`_feature/views/`)
* Tạo `[Name]ListView.tsx` (Server Component).
* Tạo `[Name]DetailView.tsx` (Server Component).
* Tạo `[Name]FormView.tsx` (Client hoặc Hybrid Form).

### ✅ Bước 4: Tạo các Actions (`_feature/actions/[name].actions.tsx`)
* Viết `indexAction`, `listAction`, `addAction`, `editAction(id)`, `deleteAction(id)`, `viewDetailAction(id)`.
* Gắn `paramsSchema = z.tuple([...])` vào các hàm nhận tham số.

### ✅ Bước 5: Tạo Barrel Export (`_feature/index.ts`)
* Export toàn bộ `schemas`, `actions`, `views`.

### ✅ Bước 6: Tạo Master Dispatcher (`app/[name]/[[...slug]]/page.tsx`)
* Import `* as moduleActions from '../_feature'` và gọi `dispatchAction(moduleActions, slug, searchParams)`.
* Thêm liên kết vào thanh điều hướng [`Navbar.tsx`](file:///Users/dylanbui/Workspaces/_NextJs/typi-code/apps/web/src/components/Navbar.tsx).
* Chạy `npm run typecheck` để xác nhận hoàn tất.
