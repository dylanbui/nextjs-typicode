# 🪵 Cẩm Nang Logging & Quản Lý File Log (Pino + Isomorphic Logger)

Tài liệu này mô tả chi tiết hệ thống ghi log và giám sát chuẩn doanh nghiệp trong dự án TypiCode Monorepo, kết hợp giữa **Isomorphic Multi-Transport Logger** và lõi tốc độ cao **Pino v10 + Pino-Roll v4**.

---

## 📦 1. Danh Mục Thư Viện & Phiên Bản Đã Cài Đặt

Dự án tích hợp các thư viện chuẩn mực hàng đầu thế giới về logging trong hệ sinh thái Node.js/TypeScript (quản lý tại [`packages/shared/package.json`](../packages/shared/package.json)):

| Thư viện | Phiên bản | Vai trò & Chức năng |
| :--- | :---: | :--- |
| 🥇 **`pino`** | `^10.3.1` | Lõi ghi log phi luồng tốc độ cao nhất thế giới Node.js (Asynchronous Non-blocking JSON). |
| 🎨 **`pino-pretty`** | `^13.1.3` | Định dạng và tô màu log rực rỡ, trực quan trên terminal trong môi trường phát triển (Dev). |
| 🔄 **`pino-roll`** | `^4.0.0` | Tự động **xoay vòng file log theo dung lượng (Size-based)** và **tự dọn dẹp file cũ (Retention Pruning)**. |

## 📁 3. Cấu Trúc Thư Mục Log Tập Trung (`logs/`)

Toàn bộ log của dự án được gom gọn vào thư mục `logs/` ở thư mục gốc (đã được thêm vào `.gitignore` để không bao giờ bị commit nhầm):

```text
typi-code/
├── logs/
│   ├── server.log               # 🖥️ Chứa toàn bộ Console Output của Next.js (lỗi compile, request traces)
│   ├── app.log                  # 📝 File log nghiệp vụ/workflow hiện tại của ứng dụng
│   └── app.2026-09-18.01.log    # 📦 File log đã xoay vòng tự động khi file chính vượt trần 5MB
```

## ⚙️ 4. Quy Tắc Xoay Vòng (Rotation) & Tự Động Dọn Dẹp (Retention)

Hệ thống được cấu hình mặc định sẵn các tham số an toàn bảo vệ đĩa cứng:

1. **Trần dung lượng (`maxFileSizeBytes`)**: `5 MB` (5,242,880 bytes).
   - Khi `app.log` đạt đến 5MB, hệ thống tự động đổi tên thành `app.YYYY-MM-DD-HHmmss.log` và tạo file `app.log` mới sạch sẽ.
2. **Số lượng file lưu trữ tối đa (`maxFiles`)**: `5 files`.
   - Khi số lượng file xoay vòng vượt quá 5, file cũ nhất sẽ tự động bị xóa ngầm (`unlink`).
3. **Thời gian lưu trữ tối đa (`maxAgeDays`)**: `7 ngày`.
   - Bất kỳ file log nào có tuổi thọ lớn hơn 7 ngày sẽ được dọn dẹp tự động.

## 💻 5. Hướng Dẫn Sử Dụng Trong Mã Nguồn

### 5.1. Import dùng chung
Bạn có thể import `logger` ở bất kỳ đâu từ package `@repo/shared`:

```typescript
import { logger } from '@repo/shared';
```

### 5.2. Các cấp độ log (Log Levels)

```typescript
// 1. DEBUG (Chỉ hiển thị khi phát triển)
logger.debug('Khởi tạo form nhập liệu', { step: 1, formId: 'product-form' });

// 2. INFO (Ghi nhận các sự kiện workflow bình thường)
logger.info('Người dùng tạo sản phẩm thành công', { 
  productId: 102, 
  title: 'Bàn phím cơ',
  userId: 'usr_abc' 
});

// 3. WARN (Cảnh báo các trường hợp bất thường nhưng chưa làm gián đoạn hệ thống)
logger.warn('Token sắp hết hạn trong 2 phút, kích hoạt auto refresh', { 
  userId: 'usr_abc' 
});

// 4. ERROR (Bắt lỗi kèm Error Object & Stack Trace)
try {
  await apiCall();
} catch (error) {
  logger.error('Lỗi khi gọi Platzi API', error, { 
    route: '/products',
    action: 'CREATE_PRODUCT' 
  });
}
```

## ⚡ 6. Hệ Thống Giám Sát Tự Động 3 Tầng (Automated Zero-Effort Telemetry)

Hệ thống được tích hợp sẵn 3 tầng giám sát tự động, lập trình viên **không cần gõ lệnh log thủ công** mà hệ thống vẫn tự động bắt và đo lường:

### 🗄️ 6.1. Tầng Database & SQL Queries ([`src/lib/prisma.ts`](../apps/web/src/lib/prisma.ts))
- **Đo thời gian chạy SQL**: Tự động bắt mọi câu lệnh Prisma ORM và Raw SQL `$queryRaw`.
- **Cảnh báo Slow Query**: Tự động phát hiện và cảnh báo `[SLOW_SQL]` khi câu lệnh chạy $\ge 50ms$.
- **Bắt lỗi cơ sở dữ liệu**: Bắt các lỗi trùng Unique Key, Foreign Key violation, hoặc lỗi cú pháp SQL.

### 🌐 6.2. Tầng HTTP Network Client ([`KyHttpClient`](../packages/shared/src/infrastructure/http-client/http-client.ts))
- **`beforeRequest`**: Tự động gắn Correlation ID (`requestId`) và ghi nhận `[HTTP_REQ] [METHOD] URL`.
- **`afterResponse`**: Tự động tính thời gian phản hồi (`durationMs`). Cảnh báo `[SLOW_API]` khi API phản hồi $> 1000ms$.
- **`beforeError`**: Tự động bóc tách JSON Error response và log `[HTTP_ERR]` kèm stack trace.

### 🎼 6.3. Tầng Master Action Dispatcher ([`ActionDispatcher.ts`](../packages/shared/src/infrastructure/router/ActionDispatcher.ts))
- **Lifecycle Tracking**: Ghi nhận `[DISPATCH_START]` khi bắt đầu xử lý Action và `[DISPATCH_SUCCESS]` khi hoàn tất.
- **Cảnh báo Action Chậm**: Cảnh báo `[SLOW_ACTION]` khi thời gian render của Server Action $> 500ms$.
- **Bắt lỗi 404 & Exception**: Tự động log tham số không hợp lệ hoặc lỗi runtime trong Action.
